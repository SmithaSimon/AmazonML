Last updated: 2026-09-27 (morning). Read this first in a new Claude Code session, together with
`README.md`, `RESULTS.md` and `Documentation_template.md`.

## Where we are

- Best validated submission: **v5**, held-out macro F_0.5 **0.9746** (tag `v5`, files in `output_v5/`).
- **v6 (embedding blocking channel) is half done.** The expensive part is finished: all Source-1
  names and the domain / non-Latin / empty-address pool records were encoded with
  `intfloat/multilingual-e5-small` (7.9 h on CPU), the per-country FAISS IVF search produced
  `work/{train,test}_cands_emb.parquet`, and `merge-emb` unioned them into
  `work/train_cands.parquet` and `work/test_cands.parquet` (column `cos_emb` added; the pre-merge
  tables are kept as `work/*_cands_v5.parquet`). The run was stopped right after the merge for
  the laptop migration.
- **To finish v6** (about 3 h on an 8-core laptop, less on more cores), from
  `code/business_entity_resolution/src`:
  ```
  python -m ber.pipeline featurize --split train
  python -m ber.pipeline train
  python -m ber.pipeline train2
  python -m ber.pipeline featurize --split test
  python -m ber.pipeline predict2
  ```
  Then compare the printed "stage-2 on val" macro F_0.5 with v5's 0.9746, record it in
  `RESULTS.md`, copy `output/` to `output_v6/`, commit + tag `v6`, and attach the zipped
  `matching_results.tsv` and models to a GitHub release.
  The merged blocking recall was NOT measured (the recall loop after the train merge was too slow
  and was stopped); the merge itself is complete: train 65.9M sparse + 9.6M embedding pairs ->
  73.5M union, test 51.2M + 7.8M -> 57.8M (log: `work/v6_blocking.log`). The "oracle" line printed
  by `train` gives the recall ceiling on the validation entities (v5: 0.987) — compare that instead.

## Portal update (2026-09-27): candidate-set size counts toward the final ranking

The organisers announced that `candidate_pairs.tsv` is reviewed and that a **smaller candidate
set per Source-1 entity ranks higher** beyond the leaderboard score. The pipeline now applies a
last filtering stage before the final (stage-2) model: only pairs with first-pass probability
>= 0.005 (always keeping each entity's best pair) are scored by stage 2 and reported as
candidates. On validation this cuts 29.9 -> 4.3 candidates per entity with recall 0.9621 vs
0.9626 (mean true matches per entity: 3.5). `predict2` writes this pruned set to
`candidate_pairs.tsv`; `train2` applies the same rule so stage 2 is trained on the same
distribution. The v5 files in `output_v5/` predate this (30 candidates per entity), so the
**v6 run (or a rerun of `train2` + `predict2` on the v5 features) is needed before the final
package**. Note: `work/model2.txt` may be a smoke-test model; `work/model2_v5.txt` is the real v5
stage-2 model — `train2` rewrites `model2.txt` anyway.

## Setting up the new laptop

Preferred: copy the self-contained handoff folder (built with `SETUP.ps1`, `START_HERE.md` and all
files from the table above already in place) and follow `START_HERE.md`: the only manual steps
are installing VS Code + Claude Code; `SETUP.ps1` installs Python 3.11, Git and the packages and
verifies the files.

Manual alternative:
1. Install Python 3.11, Git, VS Code, the Claude Code extension. Clone
   `https://github.com/SmithaSimon/AmazonML.git` (this is the project root).
2. `pip install -r code/business_entity_resolution/requirements.txt` and, for the embedding
   channel, `pip install sentence-transformers faiss-cpu`.
3. Copy the folders from the table above into the same relative locations
   (`student_resource/dataset/`, `work/`, `output_v5/`). Paths are resolved relative to the repo
   root, so nothing else needs configuring; `BER_DATA_DIR` / `BER_WORK_DIR` / `BER_OUTPUT_DIR`
   override them if you keep the data elsewhere.
4. Sanity check from `code/business_entity_resolution/src`:
   `python -c "import polars as pl; from ber import config; print(pl.read_parquet(config.WORK_DIR/'test_cands.parquet').columns)"`
   should list `cos_emb` among the columns.
5. Open the folder in VS Code, start Claude Code, and begin with: "Read HANDOFF.md, README.md and
   RESULTS.md, then continue with finishing v6."
